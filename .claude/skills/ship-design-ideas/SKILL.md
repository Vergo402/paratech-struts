# Ship Design Ideas — board → Claude Design

Take the **open** `design-idea` issues from the v4 board and project them into the Claude Design project as a guideline doc the design agent can work from. The board is the source of truth; this queue is a **disposable projection** — it is regenerated from scratch every run, so there is no dedupe bookkeeping (close an issue → it drops off the next ship).

**Branch guard:** `git branch --show-current` must be `v4-redesign`, else stop.

This skill drives the **DesignSync** tool, which only the main agent can call — run the steps below directly. Target Claude Design project: **`322a8afa-146a-4aa7-a525-673e5d1fb509`** (FieldShore v4 — Code Components). If `DesignSync` is not in the tool list, load it: `ToolSearch("select:DesignSync")`.

## 1. Pull the open ideas
```bash
gh issue list --repo Vergo402/paratech-struts --label design-idea --state open \
  --json number,title,body,url --jq 'sort_by(.number)'
```
(Epic #383 is labelled `v4` only, not `design-idea`, so it is correctly excluded.) If empty → report "No open design ideas to ship — board is clear." and stop.

## 2. Regenerate the queue doc (in the repo)
Write **`docs/guides/design-exploration-queue.md`** — overwrite it whole (it's a projection). Shape:
```markdown
# Design Exploration Queue

Open design ideas from the FieldShore v4 board (epic #383), generated by
`/ship-design-ideas` on YYYY-MM-DD. Build a mockup for each using the real
FieldShore components in this project. Each item links its board issue —
when an idea is resolved, its issue is closed and it leaves this queue.

## #<N> — <title without the "[Design] " prefix>
- **What:** <from body>
- **Where:** <from body>
- **Why:** <from body>
- Issue: <url>

## #<N> — …
```
Pull What/Where/Why straight from each issue body. Keep it faithful — this is a projection of the board, not a rewrite.

## 3. Commit the queue (pathspec only — never `git add -A`)
```bash
git add docs/guides/design-exploration-queue.md
git commit -m "[#383] design queue: ship <N> open idea(s) to Claude Design"
git push origin v4-redesign
```
The doc lives under `docs/guides/` so a future full `/design-sync` reproduces it automatically (default guideline glob) — it will never be reconciliation-deleted.

## 4. Lightweight guidelines-only push (NO component rebuild)
Stage the doc where the converter would place it, plus the recompile sentinel, then push. **Never touch `_ds_sync.json`** and never write `components/**`, `tokens/**`, or the bundle — this shortcut is valid for guideline `.md` files ONLY.

```bash
mkdir -p ds-bundle/guidelines/docs/guides
cp docs/guides/design-exploration-queue.md ds-bundle/guidelines/docs/guides/design-exploration-queue.md
printf '{"by":"design-sync-cli"}' > ds-bundle/_ds_needs_recompile
```
Then, via DesignSync (project `322a8afa-146a-4aa7-a525-673e5d1fb509`, `localDir: "./ds-bundle"`):
1. `finalize_plan` — `writes: ["guidelines/**","_ds_needs_recompile"]`, `deletes: []`. (Approval prompt; if denied, STOP — don't retry with different args.)
2. `write_files` — **sentinel first:** `[{path:"_ds_needs_recompile", localPath:"_ds_needs_recompile"}]`.
3. `write_files` — the doc: `[{path:"guidelines/docs/guides/design-exploration-queue.md", localPath:"guidelines/docs/guides/design-exploration-queue.md"}]`.
4. `write_files` — **sentinel re-arm (final write):** `[{path:"_ds_needs_recompile", localPath:"_ds_needs_recompile"}]`.

Do NOT write `_ds_sync.json`, do NOT call `delete_files`, do NOT run `report_validate` (docs-only push). (The next full `/design-sync` reconciles the anchor cleanly via its aux-hash diff.)

## 5. Report
- `Shipped <N> design idea(s) → FieldShore v4 — Code Components.`
- Project URL: `https://claude.ai/design/p/322a8afa-146a-4aa7-a525-673e5d1fb509`
- Kickoff prompt to paste in claude.ai/design:
  > Work through the items in `guidelines/docs/guides/design-exploration-queue.md` — build a mockup for each using the FieldShore components.
- Reminder: when an idea is resolved, `gh issue close <N>` so it leaves the next ship.

## Notes
- `ds-bundle/` is gitignored and may not exist between sessions — step 4 stages the file fresh each run; never assume a prior build is present.
- This moves **text**, not the 90-component bundle. Refreshing the actual components is the separate, heavier `/design-sync`.
