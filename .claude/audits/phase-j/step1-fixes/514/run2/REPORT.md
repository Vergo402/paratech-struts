## Findings and caveats
- The headline "N rows imported." still counts reverted rows (B: "2 rows imported." with one reverted). By design per the implementer; the amber line right below says what happened. Flagging it in case the orchestrator wants the headline reworded.
- Timing watch item: the verdict is meant to be ordered by IndexedDB transaction order, not by time. In all 3 reverted samples (B, B plural, phone repeat) the verdict was correctly "reverted"; the last revert was visible 1-6 ms (15 ms IndexedDB poll) or 9-19 ms (store event) before the result rendered. If the ordering ever failed, the symptom would be the amber "Saved on this device — 1 row" line while IndexedDB shows the cloud's value; I never saw that. Not proven against live Firebase, where the rollback and the rejection arrive over the network.
- Not proven live: "failed rows beside landed rows" (round-3 case: failed line, then "Other rows..."). It cannot be staged: the inventory rule validates only id and lastWriteAt, and revoking the permission refuses every push at once. It rests on the unit test only. This does not block criterion 1, which is reverted plus landed.
- Not tested: vite preview production build, a real device or real touch, live Firebase, non-dark themes.
- Heading and Done layout was not judged against the mockup (orchestrator's call); it looks as in run 1 (heading centered, lines flush left, gold Done).
