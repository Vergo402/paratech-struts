# QA brief 23 - Task Level Checklist progression

**Spec:** `docs/v4-design/09-workflows/23-task-level-checklist.md` (Phase G issue #228, epic #135). Reconciled 2026-10-13 against gate review M13/B5/M5, ADR-019, ADR-020, ADR-037, `v4-phase-status.md`, the Step 1 LEDGER (no checklist rulings), and the open deferral issues (#493-#496, #525, #504).

**What the workflow is.** A team officer on the active-operation (Operations) screen summons a "Task Level Checklist" companion panel, a two-level doctrine list (sections, each with steps). They tap a step to attest it; the step is stamped with their role title and a clock time. Tapping again un-checks it, with no confirm. Section progress is a derived count ("2 / 3"), never a bar, and no section can be bulk-completed. The gate review (M13) decided each checklist belongs to **a task/Group, not one operation-wide tree**, so two Group Supervisors never attest the same list. Tap here is deliberately different from the slide used for shore-point status.

## Setup

Fresh department per pass, on the emulator harness (see `HARNESS.md`).

1. Device A `http://localhost:5200/auth` -> Create Account (display name, `qa251-23-1@example.test`) -> Create department (apparatus: at least one engine).
2. `/operations` -> empty state button **Start Operation** (modal title "Start Operation", confirm button also "Start Operation"). Name the operation and save. Add one or two shore points so the board is not empty (not strictly needed; the checklist works on an empty board).
3. Set a role: `/command` -> **My role** (sheet title "My role") -> pick a position, e.g. Rescue Group Supervisor (assign positions in the org chart first if none are filled). Also do one pass with **no** My Role set (role stamps as "Unassigned").
4. Phone viewport 390x844 for the main pass. Re-run the placement criteria (23-16, 23-17) at 1024x768 (tablet) and 1280x800 (desktop). Both are >= 768, so "desktop posture" below.
5. Device B (cross-device story): `http://127.0.0.1:5200`, second account (`qa251-23-2@example.test`) joined to the same department via join code (Settings -> Administration or the join flow), same operation visible at `/operations`. Set a **different** My Role on B (e.g. Shoring Group Supervisor).
6. Routes: `/operations` (checklist lives only here), `/command` (My role, org chart), `/settings/department` (checklist editor section "Checklists").

## Criteria

Shipped baseline sections/steps (`src/core/checklist/baseline.ts`): Assessment (Survey the work area; Note hazards to the team), Search (Primary search; Mark searched areas; Secondary search), Access (Establish access route; Shore the route as needed), Extricate (Stabilize the patient; Remove and package), All-clear (Account for all team members; Withdraw and report). These differ from the spec wireframe wording (Search 2/3, Access 0/4, Extricate 0/2, All-clear 0/1); the spec wireframe is illustrative, so judge structure, not exact step text.

## Risks for the QA agent

- **The attach-target (23-22/23-23/23-24) is the gate's must-fix.** Read `TaskLevelChecklist.tsx`: `instanceId` is the device uid. Both of your devices therefore have separate lists by accident of being separate browsers, which can look like "per-Group" scoping. Prove it: use two **different** accounts in the **same** Group role, and the **same** account on two origins, and see what stays separate/shared. Report the true scoping key.
- **Sections are likely all open at once** (not one-at-a-time); tapping a header toggles only that section. Judge 23-07 on what you see.
- The checked row shows `Role · HH:MM` in the local time zone; two devices in the same machine agree. Do not mistake a 24-hour clock for a bug.
- The checklist stack button is **draggable** (6px pointer travel = drag, less = tap) and its position is saved in localStorage (`fieldshore_ops_stack`); it may sit at left/right edges, and a synthetic click with pointer movement may drag it instead of tapping.
- On phone the drawer is modal, so the board behind is not interactive while it is open; on >= 768px it is non-modal. Both are intended (ADR-037).
- Hash/route taps: use `location.assign('/operations')` if a `<Link>` does not respond (HARNESS).
- The 56pt row height is a spec claim; the measurement floor is 44px. Report the measured value either way.
- After an attestation with no My Role, "Unassigned" is the existing fallback (not a bug); a name is not shown, only the role title (spec also says role, not name).
