# BRIEF 11 — Adding a shore point

**Spec:** `docs/v4-design/09-workflows/11-adding-a-shore-point.md` · **Phase G issue:** #220 (epic #135). Amended by KB-7 (#313), ADR-027 (#248), ADR-029, ADR-030, and several Phase I/J rulings listed below.

**Summary.** During an active operation, an officer or IC taps **+ Add Shore Point** on the Operations board, fills a full-screen form (location, optional crew, shore type, number of shore sets, measurement, deductions, estimated load) and commits. In **two-step** operations ("Utilize Pending Card" ON) the form only describes the shore point and drops Pending Equipment card(s) on the board; equipment is assigned later from the card. In **one-step** operations (the default) the same form can also run **Find Available Struts** and **Deploy**, or fall back to **Save as Pending**. Shore type decides struts per shore (T-Shore 1, Double-T 2, 3-Post 3); a multi-strut shore is one linked group per physical shore. While still Pending Equipment a card can be edited or deleted (delete is now recoverable). Other devices see the new cards on sync.

## 2. Setup (build this first)

Follow `251-verify/HARNESS.md` for launch (`npm run emulators` + `npm run dev:emu`, :5200; device A `localhost`, device B `127.0.0.1`). Phone viewport 390x844 unless noted.

1. `/auth` → Create Account (`qa251-11-<n>@example.test`) → `/create-department` (fresh department; creator becomes Admin, which holds `manageOperations`).
2. Inventory (`/inventory`, tab bar "Inventory"): **Add apparatus**, then **Add equipment** (sheet "Add equipment — <rig>") so at least one strut model with `available > 0` exists. Needed for one-step Deploy tests; a second pass with zero stock covers the "No stock" branch.
3. Operations (`/operations`): **Start Operation** (modal title "Start Operation"). Make two operations over the pass (end the first with **End Operation**, or use a fresh department):
   - **Op A (two-step):** toggle **Utilize Pending Card** = ON, name "QA Two-Step".
   - **Op B (one-step, default):** toggle OFF (default for new ops), name "QA One-Step". Also test with **Multi-building** ON in a third op or by Edit Operation (pencil, `aria-label="Edit operation"`, flips mid-op; modal title "Edit Operation").
4. Second device B: `/auth` → Create Account, then **Join department** with the code from Settings (dept page), for cross-device criteria. Confirm B sees the op on `/operations`.
5. Add button locations: phone = floating pill "+ Add Shore Point" (bottom-right above nav, `.fs-ops-fab`); empty board shows empty state "No shore points yet" with action "Add shore point"; desktop (>=768 wide) Add lives in the board header.

Status words in the build: lanes read **Pending Equipment, Equipment Assigned, Strut Set, Cutting Station, Runner, Wood Shore Secured, Strut Equipment Returned**. Cards use short names (Pending, Assigned…). Card tab shows `#N`; group badge reads `POST 1/3`.

## 4. Superseded / Deferred

- **Field order and set** (11-03): ADR-027 (#248) restored the v3 order, Group (`assignedResource`) and Estimated Load; later SIM-IV O-9 added Side, #441 added Location capture.
- **Strut-finding location** (11-17): ADR-027 makes it a per-op mode (`Operation.inlineDeploy`, default one-step). Start Operation toggle is named "Utilize Pending Card" (ON = two-step).
- **Shore type "last-used" default**: replaced by reset to T-Shore each open (SIM-IV O-6, 2026-07-02), see 11-05.
- **Delete terminal**: ADR-030 soft delete + Restore.
- **Status change by slide only** (ADR-026): spec's pre-cutting "advance whole shore at once" is exercised by workflow 12/13, not here; do not look for an Advance button on cards.
- **Card number tab / group badge text**: ADR-029 (`#N`), badge `POST n/N`, not `[n / N]`.
- **Mockup placement of Add button**: phone FAB (Stage 2a review) replaces top-of-board button.
- **Same-shore edit lock exception**: D2 (#417, docket line 47).
- **Quantity label** "Number of shores" became "Number of Shore Sets" and its meaning (independent shores, #400).
- **Deferred:** Assign Equipment sheet and the deploy arc (workflow #221, covered by another brief); Command roll-up of `assignedResource` (ADR-027, Phase I Command tab); "Deployed X of N" polish toast (ADR-027 deferred); fast-path Add (measurement and type first, location later) was a gate-review "missing" item with no accepted decision found; recorded as a gap, not a criterion. Multi-building second half: #511 open (multi-building builds on a per-point building field only).
- **Open questions in spec**: Division picker widget (resolved by ADR-032 surface-adaptive pickers: phone slide-up sheet, desktop dropdown), Building field ordering (resolved: Building comes first), qty bound (resolved: warn >10 total cards).

## 5. Risks for the QA agent

- Spec says "Add Shore Point button always visible at top"; build is a FAB pill on phone. Not a bug.
- Pending lane is named **Pending Equipment**; the card's status word is the shorter "Pending". Both are correct.
- The number on cards (`#N`) is per physical shore, so group legs repeat the same number on purpose.
- On a new one-step op the default form shows Find Available Struts instead of a plain Add button. With no deployable stock, the submit is relabeled **Add to Pending** and a notice shows; that is intended.
- Edit/Delete only show after tapping a Pending card to expand it.
- Disabled buttons carry a reason text; read it from the DOM rather than expecting a toast.
- Geolocation permission in a headless browser will fail; record "no GPS fix" and confirm submit still works.
- Division picker carries over last-used values; a "fresh" form is only fresh for the first point.
- Shore type reset and the 3-Post wood auto-fill touch measurements and deductions. Only observe and report them; do not treat them as defects without a spec line (safety-affecting defaults require Alex's decision).
- Two-device number collisions on concurrent adds (11-33) may be genuine ordering behavior (ADR-041 canonical event order); record exactly what is shown rather than calling it FAIL on sight.
- A Deleted section appears only once a point is deleted; empty it is invisible.
