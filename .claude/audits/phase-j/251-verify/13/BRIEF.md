# #251 criteria brief 13 — Cutting

- **Spec:** `docs/v4-design/09-workflows/13-cutting.md` (Phase G issue #222); screen spec `docs/v4-design/08-information-architecture/21-cutting-station.md`.
- **Drafted:** 2026-10-13 against HEAD 903a68e on `v4-redesign`.
- **Summary.** A shore point that has reached Strut Set is slid to Cutting Station on the Operations board (group-wide: a T-Shore or 3-Post of three points moves together). It lands in the Cutting Station queue, which the cutter works first-in-first-out: Mark Cut Done (the card stays in the queue with a "Cut done" flag), then Send to Runner (the card leaves the queue and drops into a read-only "Sent to runner" tail). Each step slides back. The cut length is the one big number on the screen; it is a separate formula from the strut length (shore-type lumber, no plates, a 1½″ wedge). Stepping a card out of the station shows a "Removed from cut list" red-slash until dismissed. Since the spec was written, the station gained named saws (A, B, …) that each pull the top unclaimed cut from one shared queue (#354), and #475 fixed a case where a second cut claimed by the same saw disappeared.

## Setup (build this first, via the app's own UI)

Routes: the app has one Operations route (`src/app/routes/operations.tsx`, tab "Operations"). The Cutting Station is NOT its own route: it is the **second segment of the "Operations view" control** (`Segmented`, aria-label "Operations view"), options **Board** and **Cutting** (aria-label "Cutting Station, N in queue" when N>0; a count chip shows N). Its heading reads "Cutting Station" (`<section aria-label="Cutting Station">`).

1. Harness per `HARNESS.md` (emulators + `dev:emu` :5200). `/auth` → Create Account (`qa251-13-1@example.test`) → Create department ("QA Dept 13"). Creator becomes Admin.
2. Inventory: one apparatus (e.g. "Rescue 13") stocked with at least 3× LS 304, 3× LS 406 and 3 more struts of any model (see `05` brief for the inventory UI). Reuse the #475 recipe in `.claude/audits/phase-j/step1-fixes/475/REPORT.md` ("Setup").
3. Start an operation ("QA Op 13"). Turn **"Utilize Pending Card" off** if you want one-step inline deploy (as in #475); otherwise deploy from the Pending card.
4. Add shore points with **"+ Add Shore Point"** (the FAB on phone). Suggested set, using Area/Label to name them:
   - SP1: T-Shore, opening 5 ft 0 in. Expected cut **51½″** (60 − 2×3.5 − 1.5).
   - SP2: T-Shore, opening 3 ft 6 in. Expected cut **33½″**.
   - SP3: T-Shore, opening 4 ft 9 in (57″). Expected cut **48½″** (the spec's example).
   - SP4–SP6: a **3-Post group of three** (Group, size 3), opening 5 ft 0 in. Expected cut **47½″** (60 − 2×5.5 − 1.5). Use this for the group-wide criteria.
   - SP7: 3-Post, opening 1 ft 0 in (12″). Expected: cut floors to **0″**, hero shows the "Opening too small" chip (SME-3).
5. Deploy each point's struts and slide each to **Strut Set** ("Slide to set Strut Set"). Leave the points in Strut Set; the Cutting steps below start from there.
6. Second device (cross-device criteria only): sign in as a second member of the same department on `http://127.0.0.1:5200` (Device B; Device A is `localhost:5200`). Join via invite code (see `08` brief). Use the emulators for both.
7. Surface: phone 390×844 for everything unless a criterion names tablet (≥768px width, 1024×768 is enough). On a mouse-driven desktop pane the slides render as tap-once buttons (ADR-035); note which control you are driving in every proof.

## Superseded / Deferred

**Superseded**

- **Slide only vs. slide plus button (spec "Slide controls have Advance / Step-back button equivalents").** Superseded by ADR-026 (#248 KB-5): the slide is the only commit on touch, no hidden AT/keyboard path. ADR-035 then swaps the slide for a tap-once button on a mouse/trackpad (`(hover: hover) and (pointer: fine)`). Replacing behavior is covered by 13-01/13-17 (QA names which control it drove). Open question #37 is resolved this way.
- **Capacity "not shown" on the cut card (IA spec) / Capacity demoted.** Superseded by H1 #415 and SME-1: the station hero carries the board's over-capacity chip with the "1 of 3 struts standing" context. Covered by 13-13.
- **Empty copy "No cuts in queue" + "Move a shore point to Cutting Station to queue it".** Superseded by #389: "No cuts queued", "All cuts done" variants. Covered by 13-27.
- **Queue layout "single list of cut cards" with drag grip.** Superseded by #354: hero "cut this now" + read-only "Up next" list, one layout on all surfaces; the grip was removed (#20) in favour of a position numeral. Covered by 13-07, 13-14, 13-15.
- **Multiple saw stations (spec OQ 2).** Superseded: shipped single-device in v4.0 (#354): named saws, auto-claim, phone station-pick screen (#390). Covered by 13-24 to 13-26.
- **Cutter's cut length = deduction context on tap.** The math line is shown directly on the hero (CUT_LUMBER doctrine, #361). Covered by 13-08/13-09.
- **Cutting Station as "cutter's default screen" / "reachable from Operations sub-nav".** The sub-nav entry exists (Board / Cutting segmented control; OQ #44 resolved). A role-based default landing is not built; treat as informational.

**Deferred**

- **Priority reorder by drag-and-drop on tablet (G-16).** Handle was removed; mechanism deferred. The station renders FIFO only (IA spec says "visual handle now, mechanism deferred"). 13-16 records the absence only.
- **Cross-tablet live mirroring of saw claims** (markers reflect this device's claims only until sync): #369.
- **Ticking count badge for peer arrivals (gate review M11):** the "N new" badge (#404) is the shipped, partial answer; ticking animation deferred (OQ #45).
- **Broadcast read-only projection of the queue** and **laptop keyboard reorder:** not v4.0 (no Broadcast cutting surface found in `src/`); not driven here.
- **Gate review B6 / M6 (one-step "fat button" per cut) and M14 (propped tablet primary):** accepted deferrals (`_PHASE-G-GATE-REVIEW-VERIFICATION.md`); slide stays primary, tablet is surface-priority only.
- **Per-line Remove on a stocked rig (#525) and the #520 Sync re-send screen:** not part of this workflow.

## Risks for the QA agent

- **Slide vs button.** Under mouse emulation the controls are buttons labeled without "Slide to" ("Mark Cut Done", "Send to Runner"). Under the phone preset with touch they are sliders. Phone 390×844 via `resize_window` mobile preset may still report a fine pointer; check which control appeared before judging a missing slide.
- **Grouped mid-lane cuts.** Group-wide advance applies only to Strut Set → Cutting (and its step-back). Cutting → Runner is individual by design (#458); "only one of three moved" is correct there, not a bug.
- **Hero vs first Up next row.** With one saw the first cut is the hero and does NOT also appear as an Up next row; Up next shows the *remaining* cuts and its count chip is queue minus the hero. "N cuts in queue" counts the hero.
- **Sent-to-runner tail** also holds points that were cut earlier and are now Wood Shore Secured; it only drops a point once it is returned (Returned lane). Its cards are intentionally read-only.
- **Segment label is "Cutting"**, the heading is "Cutting Station", and the lane title on the Board is "Cutting Station". Do not log the short segment word as a copy bug.
- **#475 bounced cut:** a card bounced from Runner shows no done marker under Up next (known, deferred in LEDGER). Its "Cut done" flag only shows once it is the hero.
- **Dev StrictMode** can double-fire the first `CuttingClaimed` on first mount (known, deferred in LEDGER); it is harmless and not a FAIL unless it changes which saw holds which cut.
- **Cut length of 0″** is deliberate for tiny openings (SME-3), not a rounding bug.
- **Missing Cutting-role gate and actual-cut input** (13-34, 13-35) are probably true NOT-BUILT results; grep found no gate in the station/board slides (`usePermissions` is used only for `manageOperations`) and no actual-cut field. Record them as such without raising them as regressions.
- **Sync badge** ("1 new") only counts arrivals while the station is mounted on the receiving device and clears on leaving; opening the station after the arrival will not show it.
- Screenshots at 390 px: the Up next list sits under the hero; with two saws on desktop width the second hero is below the fold (scroll before declaring it missing).
