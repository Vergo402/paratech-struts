# QA brief 05 — Setting up inventory

**Spec:** `docs/v4-design/09-workflows/05-setting-up-inventory.md` (Phase G issue #218; screen spec `08-information-architecture/40-inventory.md`, #200).
**Summary:** Before an incident, a department loads its equipment cache: add apparatus (rigs), then stock each rig with struts, extensions and base plates, either by tapping items in a quick-add sheet and fine-tuning with a plus/minus stepper, or by importing a whole file through a 4-step validated import (pick file, map columns, check rows, review and import). It is a setup flow with no shore-point status slide. Single actor (Logistics / anyone with `manageInventory`), phone is the floor surface.

## 1. Setup (build first, using the app's own UI)
Route: `/inventory` (bottom-nav tab "Inventory"). **Not guest-first any more**: `RequireDepartment` shows "Sign in to continue" to guests and a set-up gate to members without a department (see Superseded). Steps:
1. Sign up/in as a member (emulator harness; see HARNESS.md). Create a department via the direct address `/create-department` (the only path in v4.0). The creator holds `manageInventory` and `manageData`.
2. Phone viewport 390x844. Open Inventory: expect the first-run empty state "No apparatus yet" (see 05-01).
3. For permission criteria (05-24) you need a second member without `manageInventory` (join by invite code from Settings; default member roles may differ — check the role editor; if unsure, record what you see).
4. For the held-stock criteria (05-13, 05-19, 05-27) you need an active operation with at least one shore point that has a deployed strut from the rig (Operations tab, start operation, add shore point, deploy). Do this late; most criteria need none.
5. Import fixtures: write small CSVs yourself. Get exact headers from Inventory header icon button (aria-label "Import and export inventory") then "Download template" (`fieldshore-inventory-template.csv`); "Export inventory" (`fieldshore-inventory.csv`) after stocking gives a round-trip file. Stage a malformed file (e.g. a binary/empty file renamed `.csv`) for the parse-failure case.
6. Second device (optional, only 05-30): second browser context on the same department on the emulator harness.

## 4. Risks for the QA agent
- Inventory is behind `RequireDepartment`; a guest or deptless account sees a gate, not Inventory. That is intended, not a bug.
- Button copy is sentence case ("Add apparatus", "Add equipment", "Import inventory"); do not fail on spec title case.
- "−" being disabled at 0 available is the build's version of the spec's clamp. Do not file it as a missing floor unless units can be reduced below held.
- Removing the last unit via "−" deletes the row silently; this is the spec's remove-at-0 rule, not data loss. Per-line Remove button does not exist by design (#525).
- A stocked rig's Remove is disabled only when units are held; an empty rig deletes with no confirm (intentional).
- Re-importing the same file re-stamps matched rows (last-writer-wins): a stale file can overwrite newer peer counts (ledger note). Do not report as a bug; do report if duplicates appear.
- Result "cloud" line depends on connectivity and a 4 s settle wait when online; expect a short pause after "Import n rows" before the result appears.
- Rows scoped to an unnamed/legacy apparatusId still show via a union of roster and stock; seeded data may show rigs you did not add.
- Import file input is a hidden `<input type=file accept=".csv,text/csv">`; drive it with the browser file-upload tool, not a click on the visible label.
- The PWA/service worker can serve a stale build after a deploy (two cold starts needed); use the dev or emulator harness build.
- Stat strip "on hand" ignores negative availability; "models" counts stock rows, not distinct models.
