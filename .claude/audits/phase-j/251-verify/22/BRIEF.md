# BRIEF 22 — IC Command Checklist progression

- **Spec:** `docs/v4-design/09-workflows/22-ic-command-checklist.md` (Phase G issue #227, sub-issue of epic #135)
- **Reconciled against:** ADR-010, ADR-019, ADR-020 (department checklist authoring), ADR-021/024 (IC gate), ADR-041 (canonical order), `_PHASE-G-GATE-REVIEW.md` §10 (B2 must-fix, B5 accepted deferral), `_PHASE-G-GATE-REVIEW-VERIFICATION.md`, issues #496 #494 #438 #504, `src/ui/command/{SitStat,ICCommandChecklist,ICS201Brief}.tsx`, `src/ui/primitives/{SideDrawer,ChecklistTab,NestedChecklist}.tsx`, `src/core/checklist/baseline.ts`.

**What the workflow is.** On the Command tab the Incident Commander (IC) summons a side-drawer titled "IC Command Checklist" from a small edge tab. Inside is a four-phase doctrine tree. The IC taps a step row to attest it; the row is stamped with the spelled-out role and a 24-hour time. Tapping again un-checks it, with no confirm. Phase headers show a derived "n / m" count and cannot be bulk-checked. A completed phase folds to a header; the active phase stays open. The spec also puts a live six-datum ICS-201 briefing card in this flow. The build puts that card at the top of the drawer body, above the tree, with no separate tap or dismiss. On a phone the drawer is a modal over a scrim. On a tablet or desktop (>=768px) it is a docked column beside the live board.

## Setup (build this state first)

1. Harness per `HARNESS.md`. Fresh department for this spec; emails `qa251-22-<n>@example.test`.
2. Device A (`http://localhost:5200`, 390x844): `/auth` -> Create Account -> Create department (the creator becomes the first Admin). Tab bar -> **Operations** -> **Start Operation** (modal title "Start Operation", confirm button "Start Operation"). Give it a name, e.g. "Cascade Building Fire". The founder is seeded as Incident Commander (an account-held position), so the IC gate (`useIsIC`) passes on device A.
3. For ICS-201 live values: on Operations add 3 or more shore points. Advance one to Strut Set (Secured). Add 2 hazards under **Command -> Hazard Log**, and mitigate one. Under **Command -> Org Chart**, assign a Safety Officer (the default `safety` position) so "Safety Officer" is not "Unassigned".
4. For cross-device (criteria 22-10, 22-11, 22-27, 22-28): device B (`http://127.0.0.1:5200`, separate origin). Sign in as a second member of the same department. Create the account, then join with the invite code from Settings. Do NOT make B the IC.
5. Optional second IC: use Command -> Transfer command (workflow 20) to move IC to B; then A is no longer the IC. See 22-10.
6. Routes: `/command` (Command tab home, `SitStat`). Audit log: `/audit-log` (labels: "Checklist item attested" / "Checklist item un-attested"). Template editor: Settings, `ChecklistEditor` ("FieldShore baseline" / "Customized by <dept>" badges).
7. Phone viewport 390x844 for everything except criteria marked tablet (768x1024) or desktop (1280x800; the Command Deck begins at 1024px, the docked drawer at 768px).

## Risks for the QA agent

- **Wording drift is not a bug.** Phase and step names in the spec ("Phase II - Ongoing command", "Confirm accountability (PAR)") are illustrative. The build baseline is "Phase I - Size-up" ... "Phase IV - Demobilization" with hyphen, not an em dash. Count format is "n / m" with spaces.
- **No tap on "ICS-201 briefing".** The spec has the IC tap into a card and dismiss it. The build embeds the card at the top of the drawer. There is no separate screen or dismiss. Judge on content (22-23 to 22-26).
- **Tab hidden while the drawer is open.** The spec's "tap tab to close" is not how the build closes. Use Close/Esc.
- **IC gate is whole-surface.** A non-IC device sees no tab at all. Make sure device A really holds IC before concluding the tab is missing. After a command transfer the old IC loses the tab.
- **Phone vs dock behavior.** <768px = modal with scrim; >=768px = docked, no scrim. The Command Deck rail layout begins at 1024px; at 768 to 1023 the Command screen is still the stacked phone column with a docked drawer.
- **Time zone and clock.** Attribution is local 24-hour HH:MM. Compare with the browser clock, not UTC.
- **Zero-state ICS-201.** "Open hazards" reads "None" at 0, not "0". "Safety Officer" reads "Unassigned" until the position has a leader. Neither is a bug.
- **TanStack tab routing.** If tapping the Command tab does not route, use `location.assign('/command')`.
- **Counts on collapsed phases.** Auto-collapse only applies to a fully complete phase. Opening one manually is allowed and stays open.
- **Offline.** The spec has no offline story for this flow; 22-28 is the only offline criterion. Do not expect a visible offline indicator in the drawer.
