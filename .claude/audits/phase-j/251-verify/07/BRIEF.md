# QA brief 07 — First-run / department setup

**Spec:** `docs/v4-design/09-workflows/07-department-setup.md` (Phase G issue #231, epic #135). Related: `08-information-architecture/71-dept-setup.md`, ADR-017 (founding Admin), ADR-022 (multi-use + QR code), ADR-015 (never a gate), ADR-034 (first-run welcome carve-out).

**Summary.** A signed-in person with no department stands one up in under two minutes: type one field (department name), tap Create department, become the first Admin, and get a QR + 8-character invite code in a success sheet to share with the crew. It is deferrable (skip, keep working as a guest/with Quick Find) and additive (no un-create, no delete in v4.0). A post-v3-migration "Claim department" banner is in the spec but the v3 carry-over was re-scoped to a CSV re-import (#264), so no migration exists.

## Setup

Per HARNESS.md (emulators + `npm run dev:emu` on :5200). Device A = `http://localhost:5200` (or 127.0.0.1 if localhost is stale), device B = the other origin. Start both from a clean origin.

1. Cold open as guest: app lands on Quick Find (`/`), no overlay.
2. Create an account: `/auth` -> segmented control "Create Account" (fields display name, email `qa251-07-<n>@example.test`, password >= 6) -> button "Create Account". Expect the app to client-navigate to `/create-department` because no department exists (`afterAuth` in `src/ui/auth/AuthScreen.tsx`). An ADR-034 welcome tour may appear after account creation (skippable) — dismiss with Skip if it blocks.
3. Second device B (cross-device check only): a second account created fresh, used to join with the code (route `/join-department`, workflow 08 is another agent's; use it only to prove the code works).
4. Alternate entry points to cover:
   - Gate: signed in with no department, tap Operations/Inventory/Command tab -> `RequireDepartment` card titled "Set up your department" (`src/ui/dept/RequireDepartment.tsx`).
   - Settings -> Department (`/settings/department`, `src/app/routes/settings/DepartmentPage.tsx`) shows "Create new department" only when the member has no department.
5. Routes verified in `src/app/router.tsx`: `/create-department` (pre-shell, outside the tab shell), `/join-department`, `/auth`, `/operations`.

## Superseded / Deferred

- **Superseded (ADR-022 / gate B4):** the invite code is multi-use, regenerable, QR + code (not one-time/24h). Spec already says this; restated as 07-11, 07-13, 07-21.
- **Superseded (#264, Phase J Stage B, `.claude/audits/phase-j/264-reimport/REPORT.md`; `.claude/rules/v4-phase-status.md`):** v3 -> v4 carry-over is a fresh-start CSV re-import into a NEW v4 department, not a migration. The "Claim department" post-migration banner/path has no purpose; 07-29 stays Testable only so QA records NOT-BUILT.
- **Superseded (ADR-025 addendum, #439):** second way a member lands in a department is admin provisioning (User Manager) with no invite code; not part of this flow.
- **Superseded (ADR-034):** after deliberate account creation a skippable welcome tour may precede the create route; the spec has no such step.
- **Deferred (spec Open Q 1):** address / department type / default incident Level at setup — name-only in v4.0, edit later in Settings.
- **Deferred (spec Open Q 3, v4.1+):** founding-Admin transfer ceremony; extra Admins are made in User Manager (`/users`, workflow 30).
- **Deferred (spec Open Q 4 / #274-class):** multi-department membership and switching; in-app dept switch/leave/delete is WON'T-FIX (Alex 2026-07-01). Phase status: a second department is created only via the direct `/create-department` address.
- **Deferred (#525, v4.1):** per-line Remove of stocked rig items (unrelated to setup; here only so QA does not log it).
- **#520:** ADR-042 tamper rules R1-R3 wait on a Sync re-send screen; not testable here.

## Risks for the QA agent

- Button copy differs from the spec: build says **"Skip for now"**, spec says "Continue as guest"; build adds **"Join an existing department"**. Copy drift, not a bug. The "Back" button also exits to `/operations`.
- "Create new department" in Settings appears only when the member has NO department; an existing member will not see it. To make a second department, navigate directly to `/create-department` (rule recorded in phase status). Creating it while already in a department is not specified by 07.
- Create ends in a **full page reload** (`window.location.assign('/operations')`) on Done/dismiss. State read after Done requires re-installing helpers; the sheet intentionally stays up until then so the cloud writes finish.
- createDepartment is **local-first**: the department "exists" locally even if the cloud write is pending/rejected (offline or rules not yet deployed). Do not treat a successful sheet as proof the cloud has it; read the emulator REST (`?ns=fieldshore-database-default-rtdb`, `Authorization: Bearer owner`) for `/orgs` / invite code resolver for cross-device claims.
- Invite code is random 8 glyphs; spec example `HAMD-4F2K` (name-derived) is illustrative only.
- Dev StrictMode may double-mount; prefer a `vite preview`-style check for focus/double-create concerns if results look odd.
- Name errors: blank is blocked by the disabled button, so "Department name is required." is reachable only through the service; do not log the disabled button as FAIL.
- Spec says the success surface "enters the shell as Admin" on Done; the Admin badge in the sheet is visible only before the reload.
- A stale `localhost:5200` profile can mislead (LEDGER Task 2 note): prefer `127.0.0.1:5200` for the founder device if sign-in state looks wrong.
- Pre-existing queued join intent: createDepartment now clears a queued join (final fix wave F1); if QA previously attempted a join offline on the same origin, clean the origin first.
