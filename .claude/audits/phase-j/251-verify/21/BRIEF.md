# Brief 21 — Hazard log

**Spec:** `docs/v4-design/09-workflows/21-hazard-log.md` · **Phase G issue:** #226 (epic #135) · **Drafted:** 2026-10-13 against `v4-redesign` @ 903a68e

**What the workflow is, in plain words.** The Hazard Log is the incident's ICS-208 hazard register. Anyone in the field adds a hazard (type, location, severity, optional notes) from a bottom sheet; open hazards sort worst-first, newest-first, and mitigated ones drop to a "Mitigated" section. Anyone can open a hazard, mark it mitigated (records who and when) and reopen it. A hazard whose location clearly names exactly one Division also puts a red "HIGH / MED / LOW hazard" badge on every shore-point card in that Division. The badge only informs: the slide-to-advance control always works. There is no safety-hold status anywhere. The register exports as a file. Everything travels by the normal sync, no push.

## Setup (build this state first)

Emulator harness (HARNESS.md): device A = `http://localhost:5200`, device B = `http://127.0.0.1:5200`. Phone viewport 390x844 unless stated. Fresh department for this spec.

1. **Account A (founder, IC):** device A `/auth` -> Create Account (`qa251-21-a@example.test`) -> `/create-department`. **Account B (member):** get the invite code from A (Settings -> Department), device B `/auth` -> Create Account (`qa251-21-b@example.test`) -> `/join-department`. Optional guest: a third origin/profile opened without signing in (guest-first cold open) to probe "any role".
2. **Apparatus:** A, Inventory (`/inventory`), add "Engine 3" with a few struts so a shore point can be deployed later (only needed for the advance-slide check).
3. **Operation:** A, Operations (`/operations`) -> "Start Operation" (modal), name "Cascade Building Fire".
4. **Shore points (via the "Add Shore Point" modal, `AddShorePointModal`; floor field = DivisionPicker):** create at least five: two in **Division 2**, one in **Division 3**, one in **Division 1**, one in **Basement 1 (Division -1)** if the picker offers sub-grade. Leave one Division-2 card in Pending with "Engine 3" available so the advance slide is live; the Operations tab has Board / List / Division views (Segmented), plus Quick View (tap a card) and Cutting Station.
5. **Safety Officer (optional, for the header chip):** Command -> Org Chart -> node "Safety Officer" -> assign a person (covered by brief 20).
6. Open device B on `/operations` for the same operation before the cross-device criteria.

**Routes/labels verified in `src/`:** Hazard Log lives on the **Command** tab (`/command`, `SitStat` -> `CommandRail`). Phone (<1024 wide): the rail's **"Hazards"** entry row (meta "No open hazards" or chip "N open · SEV" plus top location) raises a Sheet titled **"Hazard Log"**. Deck (>=1024): Segmented "Org Chart | Hazard Log" (aria-label "Command workspace view") in the right pane. Code: `src/ui/command/HazardLog.tsx`, `IncidentChips.tsx`, `CommandRail.tsx`, `src/ui/operations/HazardBadge.tsx`, `src/core/hazard/{location,reducer}.ts`. Operations board strip: `IncidentChipStrip` (Safety chip + hazard chip) under the board meta line.

## Risks for the QA agent (likely mistaken for bugs)

- **Division-2 means the shore point's Division, not a side.** "Side D 2" and "B 2" (spaced) are deliberately NOT Divisions. A bare "2" as the whole location works, "2nd floor" does not. "B1" is basement 1 (Division -1), not floor 1.
- **Badges show only OPEN hazards;** a mitigated hazard's card badge vanishing is correct. A Division with several open hazards shows only the worst severity, once.
- **The badge is on the card, not the slide control.** An advance that fails for out-of-stock/capacity reasons is a different feature; only a hazard-caused block is a bug.
- **No Cutting Station badge and no chip strip on `/inventory` or `/quickfind`** are by design (Alex 2026-10-11). Check Cutting Station and decide NOT-BUILT only against the "persistent header" wording (21-18).
- **Reporter names:** non-admins see "You" / "A teammate" instead of display names (member list read is permission-gated). Admins (account A) see names. Not a bug.
- **Export is a CSV**, so a missing ICS-208 form layout is #494, not a FAIL. Date cells use `toLocaleString`; "Reported by" columns are device uids.
- **Two origins = two devices**; the hazard chip count is "open hazards, worst severity", so "3 open · HIGH" is not three HIGH hazards.
- **Sheet scrim-close and TanStack `<Link>` taps may not work with synthetic events** (HARNESS); use Esc, reload or `location.assign('/command')`.
- **Add Hazard disabled until Location has non-space text;** the button text becomes "Adding…" briefly. A stale frame right after commit is worth a screenshot probe but is not by itself a FAIL.
- **Chip tap navigates to `/command` but does not open the Hazard Log** (Phone: you still tap the "Hazards" row). Do not call that a missing link without checking the spec: it only says reachable in one tap from SitStat.
