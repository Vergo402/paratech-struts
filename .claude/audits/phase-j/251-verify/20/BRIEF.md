# Brief 20 — Role assignment and command transfer

**Spec:** `docs/v4-design/09-workflows/20-role-assignment-command-transfer.md` · **Phase G issue:** #225 (epic #135) · **Drafted:** 2026-10-13 against `v4-redesign` @ 903a68e

**What the workflow is, in plain words.** Two things on the Command tab. (1) Role assignment: any signed-in device declares which ICS position it is staffing ("My role"), and the Incident Commander puts apparatus or people into positions on the org chart, restructures it, and removes positions. (2) Command transfer: the standing Incident Commander picks an incoming commander on a full-screen takeover. That only starts a handshake. The outgoing IC keeps command (and End Operation) until the incoming person accepts; cancel or decline leaves command where it was (ADR-021). Everything is written to an append-only role history. Later changes: a person's position follows their account across devices (commit 552faca); individual and apparatus targets get a 4-digit accept code (#425); a single shared tablet can complete the accept (#401); apparatus on scene are first-class recipients (#489).

## Setup (build this state first)

Use the emulator harness (HARNESS.md): device A = `http://localhost:5200`, device B = `http://127.0.0.1:5200`. Phone viewport 390x844 unless stated.

1. **Account A (outgoing IC, "Reyes"):** device A, `/auth` -> radio "Create Account" (display name, email `qa251-20-a@example.test`, password) -> `/create-department` (fresh department for this spec). Creator becomes first Admin.
2. **Account B (incoming, "Okafor"):** get the department invite code from device A, Settings -> Department ("Invite code"). Device B: `/auth` -> Create Account (`qa251-20-b@example.test`) -> `/join-department` with the code. Optionally a third account C the same way (observer: neither IC nor target).
3. **Apparatus:** on A, Inventory tab (`/inventory`), add two apparatus (e.g. "Engine 3", "Battalion 1"). Settings -> Apparatus types if a type is needed.
4. **Operation:** device A, Operations tab (`/operations`) -> "Start Operation" (modal, title "Start Operation"), name it "Cascade Building Fire". Add 2-3 shore points so the brief counts are non-zero; deploy "Engine 3" to one shore point (or assign it on an org node) so it counts as "on scene". Log one hazard (Command -> Hazards) so "Open hazards" is non-zero.
5. **Default roles:** the founding account should hold Incident Commander by default (the spec's precondition). Command tab (`/command`) shows the Incident Commander card row with the gold underline. On phone, the org chart is the "Org Chart" entry row -> Sheet titled "Org Chart"; the "My role" chip and full-screen button sit at the top of that sheet. On the Deck (>=1024 wide) the chart is inline.
6. Make sure device B is on `/command` with the same operation visible (sync) before the cross-device criteria.

Routes verified in `src/`: `/command` (CommandScreen -> SitStat), `/operations`, `/inventory`, `/settings/department`, `/auth`, `/create-department`, `/join-department`. Code: `src/ui/command/{CommandRail,TransferCommand,MyRoleSheet,NodeSheet,OrgChart,OrgTree,ICS201Brief}.tsx`, `src/core/org/{transfer,span,self}.ts`.

## Risks for the QA agent

- **Transfer button names differ:** trigger is "Transfer"; takeover title "Transfer Command"; confirm button "Hand over command". These are not bugs; report copy as SPEC-DRIFT only if you find no later decision.
- **Account target vs code:** transferring to a Department member (account) has NO accept code and only that account sees Accept. Transferring to a typed name or an apparatus has a code and the same-device Accept. Do not call the missing code on account targets a bug.
- **Soft claim:** any device may accept an individual/apparatus transfer by design (code is a fat-finger gate). Do not file "C can accept" if C knows the code.
- **Shared-device records:** on same-device accepts both events carry the same device uid; role history shows no separate "who".
- **Transfer button hidden while pending** is intentional; also hidden for non-IC.
- **Individual or apparatus as IC** makes every device `commandsIC` true (pre-auth permissive), so after a hand-over to "Chief Alvarez" the observer device B may still show IC controls.
- **Org-chart IC node is neutral;** the single gold IC mark is the Command rail underline.
- **Spec shows a seven-item My Role list;** the build lists every position, including added ones.
- **Sheet scrim-close and TanStack `<Link>`** may not respond to synthetic input; use `location.assign` and reload as HARNESS says.
- **The live region on accept** only exists on the accepting device and unmounts quickly; sample the DOM right after the tap.
- **Operation switching:** only one department per account; do not try to reuse A in two departments.
