# Plan: v3.8.2 — Fix Firebase inventory write validation

## Context
1 bug report from Firebase feedback (v3.8.1, dept hfd217). Filed as [#67](https://github.com/Vergo402/paratech-struts/issues/67). Root cause: Firebase validate rule field name mismatch blocks ALL inventory writes since v3.7.0.

---

## Feedback Triage

### Bug for this release

**#67 — Inventory not decrementing on deploy (Firebase PERMISSION_DENIED)**

**Root cause:** The `database.rules.json` validate rule on `inventory/$itemId` checks for a `name` field:
```json
".validate": "newData.hasChildren(['name', 'quantity', 'available'])"
```

But all inventory items use `model` as the field name:
```json
{"model":"AT 37-58", "quantity":6, "available":6, ...}
```

Any write to any inventory item (deploy decrement, return increment, manual edit) fails validation. Firebase returns `PERMISSION_DENIED` (misleading — it's a validate failure, not a write-rule failure). This has been broken since v3.7.0 added the security rules.

**Impact chain:**
1. `deployShorePoint()` → `firebaseSave(..., 'transaction', ...)` → PERMISSION_DENIED
2. Transaction failures are NOT queued (`app.js:847`: `if (method !== 'transaction')` skips queue)
3. Local in-memory inventory decrements correctly
4. Firebase listener (`inventoryRef.on('value')` at line 1333) re-syncs server data (un-decremented)
5. Local state overwritten → inventory shows pre-deployment counts

**Evidence:**
- Diagnostic log: 70 `set` writes to `/departments/hfd217/inventory/{id}/available` all failing with `PERMISSION_DENIED` (queued from older code that used `set` method)
- Firebase data: AT 37-58 shows `available:6` / `quantity:6` despite 6 deployed across 2 shore groups
- 3 authenticated UIDs in `members` — the write rule passes; it's the validate that blocks

### Secondary observation — stale plate selection (UX, not code bug)

The user reported 6x6 channel bases deployed but 4x4 was selected. The plate selection code is correct (`plateId` matching at line 3616). The likely cause: `plateSelections` persists across shore point deployments — a previous deployment used 4x4, and the selection carried over without the user noticing. Not a code bug, but noted for future UX improvement (auto-reset picker between deployments).

## Implementation

### Fix 1: Validate rule — change `name` to `model` (critical)

**File:** `database.rules.json`, line 18  
**Current:** `".validate": "newData.hasChildren(['name', 'quantity', 'available'])"`  
**Fixed:** `".validate": "newData.hasChildren(['model', 'quantity', 'available'])"`  
**Deploy:** `firebase deploy --only database --project paratech-c3ab4`

### Fix 2: Clear stale pending writes on version upgrade

The 70 queued writes from v3.7.5 use `set` with absolute values. Even with the validate fix, replaying them would overwrite current inventory values with stale snapshots. Need to discard them.

**File:** `app.js`, `flushPendingWrites()` (~line 862)  
**Approach:** Add version-aware filtering — discard writes from a different `appVersion` than the current one. Add `appVersion` to queued writes in `firebaseSave()` catch block (line 846).

In `firebaseSave()` catch (line 846):
```javascript
const op = { path: ref.toString(), method, timestamp: Date.now(), retries: 0,
  lastError: err.message || String(err), appVersion: APP_VERSION };
```

In `flushPendingWrites()` viable filter (line 870):
```javascript
if (op.appVersion && op.appVersion !== APP_VERSION) {
  console.warn('Discarding write from old version:', op.appVersion, op.path);
  logSyncEvent('discard_version', { path: op.path, method: op.method, fromVersion: op.appVersion });
  return false;
}
```

Where `APP_VERSION` is the existing `appVersion` value (~line 2092 area) — promote to a module-level constant.

### Fix 3: Log transaction failures (observability)

Transactions fail silently (not queued). Add `logSyncEvent` for transaction failures so diagnostics capture them.

**File:** `app.js`, `firebaseSave()` catch block (~line 847)

After the `if (method !== 'transaction')` block, add:
```javascript
if (method === 'transaction') {
  logSyncEvent('transaction_failed', { path: ref.toString().replace(/.*firebaseio\.com/, ''), error: err.message || String(err) });
}
```
