# Plan: v1.9.0 — Feedback Bug Fixes & UX Improvements

## Context

17 new feedback items from Firebase (8 bugs, 9 features). This release focuses on the 8 bugs and 3 quick-win features. Larger features (ICS hierarchy chart, pending equipment cards, individual roles) deferred to v2.0.0.

---

## Bugs for This Release

### Bug 1: Excel export/template broken, apparatus show as DB IDs
**Issue:** #10
**Symptom:** Export and template Excel files are broken. Apparatus column shows Firebase push IDs instead of human-readable names.
**Investigate:** `exportInventory()` (line ~4238) and `downloadTemplate()` (line ~4265). The `Apparatus` field is set to `item.apparatus` which is the raw Firebase ID. Need to run it through `getApparatusName()`.
**Fix:** In `exportInventory()`, change `Apparatus: item.apparatus || ''` to `Apparatus: item.apparatus ? getApparatusName(item.apparatus) : ''`. Check if template also needs apparatus names (currently hardcoded to empty — may be fine). Test both export and import round-trip to make sure import still works with names or IDs.

### Bug 2: Cannot open layout cards under Command tab
**Issue:** #11
**Symptom:** Layout cards in the Command view don't open/expand when tapped.
**Investigate:** `renderCommandView()` (line ~3673). The layout section (line ~3759) renders cards with hierarchy groups but they're display-only divs — no `onclick` handler to drill into the group or show shore points. Compare with Operations drill-down which uses `onclick` to navigate.
**Fix:** Add click handlers to layout cards that either expand to show shore point details inline, or navigate to the Operations drill-down at that hierarchy level. The simplest fix: make each layout card clickable to switch to Operations view filtered to that group.

### Bug 3: Apparatus roles not populated on role list
**Issue:** #12
**Symptom:** After assigning roles to apparatus, the role list doesn't immediately reflect the change.
**Investigate:** `selectRole()` (line ~2667). After setting `activeOperation.roles[roleTarget]`, it syncs to Firebase but may not trigger a re-render of the operations view. Check if `renderOperationsView()` is called after the modal closes.
**Fix:** Ensure `renderOperationsView()` (or whichever view is active) is called after `selectRole()` completes and the modal closes. The apparatus chips in the operations view (line ~2929) already read from `activeOperation.roles` — they just need a re-render trigger.

### Bug 4: External equipment requires both dept and apparatus
**Issue:** #13
**Symptom:** Adding external equipment forces the user to fill in both department name and apparatus name. Should accept either one.
**Investigate:** The external equipment add flow — look for the modal/form that collects dept and apparatus. Search around line ~2816 where `externalEquipment` is created.
**Fix:** Make dept and apparatus fields optional (require at least one, not both). Update validation to accept either field.

### Bug 5: Quick Add connector plates not sorted alphabetically
**Issue:** #14
**Symptom:** Plates in the Quick Add grid appear in `BASE_PLATES[]` array order, not alphabetical.
**Investigate:** Quick Add plates render at line ~2457. Iterates `BASE_PLATES` directly with `for (const plate of BASE_PLATES)`.
**Fix:** Sort `BASE_PLATES` by name before iterating: `const sortedPlates = [...BASE_PLATES].filter(p => p.id !== 'none').sort((a, b) => a.name.localeCompare(b.name))`. Use `sortedPlates` in the render loop. Apply same sort to plate picker grids in shore point form (search for other `BASE_PLATES` iterations around lines ~1190, ~1486).

### Bug 6: Available inventory not sorted by type then alphabetical
**Issue:** #15
**Symptom:** Inventory list isn't ordered logically. Should be: struts first, then extensions, then plates — each group alphabetical.
**Investigate:** `renderInventory()` (line ~2311). Check how `localInventory` is iterated and rendered.
**Fix:** Sort the inventory items before rendering: struts first (by model name), then extensions (by system then length), then plates (by name). Apply to both the main inventory tab and the available inventory sidebar in operations.

### Bug 7: Extension rules wrong for grey and gold struts
**Issue:** #16
**Symptom:** Three issues: (1) Grey/AcmeThread struts should max 2 extensions totaling 36" (3'), (2) Gold/LongShore struts should accept only 1 extension regardless of length, (3) No results shown past 16' even though LS 1016 extends to 198" (16.5') without extensions.
**Investigate:** `findStrutCombinations()` (line ~1746). The combo generator at line ~1772 creates all pairs `[e1, e2]` without system-specific limits. The only constraint is `extTotal > strut.extended` (line ~1783). No max-extension-count rule per system.
**Fix:**
- Add system-specific extension rules after combo generation:
  - `LongShore`: max 1 extension (`extCount <= 1`)
  - `AcmeThread`/`LockStroke`: max 2 extensions, total extension length <= 36"
- Check the 16' issue: LS 1016 has `extended: 198` (16.5'). A 192" (16') measurement should match without extensions. If it doesn't, there may be an off-by-one or the search isn't reaching it. Test with 192" input.
- The `EXTENSIONS.LongShore` array is `[12, 24, 48, 67]` — verify these are correct per Paratech specs.

### Bug 8: Actual cut measurement needed before "cut done"
**Issue:** #17
**Symptom:** Cut Table flow requires marking "Cut Done" before entering the actual measurement. User wants to enter the actual cut measurement first.
**Investigate:** `renderCutTableView()` (line ~3803). Check the two-phase flow: Phase 1 shows "Mark Complete" button, Phase 2 shows actual measurement input + "Send to Runner". The complaint suggests Phase 1 should include the measurement input.
**Fix:** Combine the phases — show the actual measurement input field alongside the "Mark Complete" button so the cutter can enter the measurement and mark complete in one step. The "Send to Runner" step can remain separate.
