# Plan: v3.7.3 — Empty-state clarity for strut recommendations

## Context

Single new bug report from HFD 217 against v3.7.2: at 73" effective opening with Engine 169/170/TL15 assigned, the recommendation panel showed "no struts available." Investigation confirmed 17 strut combos geometrically match 73" (AT 37-58 + 36" ext, LK 55-89 base, LS 406 base, etc.) — none stocked on the assigned apparatus.

The bug is a UX gap, not a math/logic error. The current empty state conflates two distinct cases: (a) no geometrically valid strut exists, (b) valid struts exist but none are in the assigned inventory. The user can't tell which they're hitting, so the message is misleading.

**Target version:** v3.7.3 (PATCH — UX fix, no new features)

## Implementation

### #63: Distinguish "no geometric match" from "no inventory match"

**Issue:** [#63](https://github.com/Vergo402/paratech-struts/issues/63)
**Symptom:** Rescuer sees "no struts available" and doesn't know whether to look for a different opening size or to call for more equipment from another apparatus.
**Investigate:**
- `findStrutCombinations(requiredLength, estimatedLoad, sfIndex, inventory, systemFilter, deductions)` in `app.js:151` — accepts `inventory` parameter; when `null`, ignores apparatus filtering.
- The two call sites that drive recommendations: Quick Find (`findStruts()` near top of search workflow) and Shore Point form recommendations (in `openShorePointModal()`).
- The empty-state rendering — find where the "no struts available" message is built. Likely uses a guard like `if (results.length === 0)` in the render path.

**Fix approach:**

In each caller, when the inventory-scoped call returns 0 results AND the operation has assigned inventory:
1. Re-run `findStrutCombinations()` with `inventory = null` to get the unrestricted set.
2. If that returns matches → show "No matching struts on assigned apparatus. The following Paratech models would fit if available:" followed by a compact list (model + extensions, no qty/capacity decoration since the user can't deploy them anyway).
3. If unrestricted also returns 0 → keep the current "no struts available" message (genuinely impossible geometry).

Render the second-pass list with a distinct style (muted color, "informational" not "actionable") so it doesn't look like a deployable recommendation.

**Edge cases:**
- Operation has no assigned apparatus → already shows unrestricted results (no change needed).
- User has the deduction toggle on and one of the deducted plates is missing from inventory → second-pass shows what struts would fit if plates were available. This is a follow-on case; for v3.7.3 keep it simple — only re-run the strut search, not the plate-availability search.
- "Unrated zone" warnings still apply on the second-pass list.

**Test:**
- Operation with apparatus that has no struts → request 73" → expect to see AT 37-58 + 36" ext, etc. with informational styling.
- Operation with apparatus carrying AT 37-58 → request 73" → expect normal recommendation (no second-pass list).
- Request impossible length (e.g., 500") → expect "no struts available" (unchanged).
- Empty op (no apparatus assigned) → request 73" → expect normal unrestricted recommendation (no second-pass list).
