### Phase 2A — Service Worker Network-First (A3)
**Files:** `sw.js`
**Strategy change:** HTML and JS files use network-first; everything else stale-while-revalidate.
```javascript
self.addEventListener('fetch', (event) => {
  const url = event.request.url;
  if (url.includes('firebasejs') || url.includes('firebaseio') || url.includes('sheetjs')) return;

  // Network-first for HTML and JS — never run stale code during an op
  const isCritical = url.endsWith('.html') || url.endsWith('app.js') || url.endsWith('/');
  if (isCritical) {
    event.respondWith(
      fetch(event.request).then((response) => {
        if (response.ok) {
          const clone = response.clone();
          caches.open(CACHE_NAME).then((cache) => cache.put(event.request, clone));
        }
        return response;
      }).catch(() => caches.match(event.request))
    );
    return;
  }

  // Stale-while-revalidate for static assets (CSS, images, manifest)
  // [existing logic]
});
```

### Phase 2M — Combined measurement input (E10)
**Files:** `index.html:398-428` (sp/qf measurement rows); `app.js:1378` (`getMeasurementInches`)

```javascript
function parseMeasurement(text) {
  if (!text) return 0;
  text = text.trim();
  // Try numeric first
  if (/^\d+(\.\d+)?$/.test(text)) return parseFloat(text);
  // Try "7'4-1/2\"" or "7'4 1/2\"" or "7' 4-1/2"
  const m = text.match(/^(\d+)'(?:\s*(\d+))?(?:[\s-](\d+)\/(\d+))?"?$/);
  if (m) {
    const ft = parseInt(m[1]);
    const inch = m[2] ? parseInt(m[2]) : 0;
    const frac = (m[3] && m[4]) ? parseInt(m[3]) / parseInt(m[4]) : 0;
    return ft * 12 + inch + frac;
  }
  return null; // fall back to legacy three-field UI
}
```

# v4.0.0 — Multi-Agency & Doctrine (MAJOR)

**Scope:** Architectural changes — security, multi-tenancy, NIMS-doctrine ICS structures, operational periods, after-action exports. Breaking schema changes. This is a planned rewrite of the dept boundary.

## Files modified

| File | Changes |

| `style.css` | Agency badge palette |
| `index.html` | Auth/onboarding flow, operational period UI, AAR export UI, ICS structure presets |
| `sw.js` | Strategy refinements, cache name bump |

## Implementation outline

### Phase 3A — Authentication & per-write attribution (C6, H4)
- Firebase Anonymous Auth on init; get `uid`
- Store local "device profile": `{uid, displayName, agency, role}`
- Every `firebaseSave` decorated with `{by: uid, agency, at: serverTimestamp}` via update helper
- Firebase Security Rules: read/write require auth, agency-tagged writes only allowed by members of that agency
- Migration: on first auth-mode load, prompt user to claim their device with name + agency

### Phase 3B — Agency tagging on records (C1, C5)
- Add `agency` field to apparatus, inventory items, shore points, external equipment, roles
- Migration: existing records get `agency: settings.name` (the user's dept name) as best-effort
- UI: agency badge on every apparatus chip, drilldown item, shore point card
- Color palette assigned per agency string (hash → color)

### Phase 3C — Multi-tenancy: subscribe to host op (C5)
- New Firebase structure: `/operations/{opId}/...` (NOT nested under dept)
- `/depts/{deptId}/members/{uid}` for membership
- `/operations/{opId}/agencies/{agencyId}` listing who's joined
- Each device can be a member of multiple agencies; chooses one per op
- Reads merged across agencies; writes tagged with the device's current agency

### Phase 3D — NIMS-doctrine presets (C2)
- New "Choose ICS Template" on op start:
  - Working Fire (Type IV/V): IC + Operations + Safety
  - USAR Task Force (Type III): IC + Safety + PIO + Liaison + Operations + Planning + Logistics + Branch I/II + Groups
  - Major Collapse (Type I/II): Full ICS + multiple Operations Section Chiefs, Branches, Divisions, Groups, Strike Teams
- Add `roleType` field (Command/General/Branch/Division/Group/Strike Team/Task Force) — affects rendering and span rules
- Allow Safety reparent under Branch with confirmation
- Support Unified Command (multiple co-ICs at root)

### Phase 3E — Operational periods (C3)
- New schema: `activeOperation.operationalPeriods[]` with `{num, start, end, briefingTime, objectives, ICs}`
- Default 12-hour period, IC-settable
- On boundary: snapshot all role assignments + SP statuses → period archive
- "Current OP: 4 (1900-0700)" badge on Command view
- Period-aware reports (per-period role list, SP changes, etc.)

### Phase 3F — Comprehensive AAR export (C4)
- Export Operation as a ZIP with:
  - ICS-201 (Incident Briefing) PDF
  - ICS-203 (Org Assignment List) — one per op period
  - ICS-204 (Assignment List)
  - ICS-211 (Check-in List) for apparatus
  - ICS-215 (Operational Planning Worksheet)
  - Shore points spreadsheet with full timeline
  - Hazards log
- Triggered from Archive view or "Export Mid-Op" on Command page
- Uses XLSX (already lazy-loaded) and a PDF library (jsPDF)

### Phase 3G — Firebase first-connect data migration (A1)
- On listener first-fire (use a flag), if `snap.exists() === false` AND local data exists:
- Block listener from overwriting; instead push local to Firebase with `set`
- Once Firebase has the data, normal listener resumes
- For operations: prompt user to push local op to remote dept (one-time migration)

### Phase 3H — Transactional writes for shared structures (A4)
- Refactor `assignedApparatus`, `customRoles`, `roles` updates to use:
  - `.update({path: value})` for single-field changes
  - `.transaction()` for composite (roles object mutations)
- This prevents last-writer-wins from clobbering concurrent edits

### Phase 3I — XSS hardening pass (H3)
- Audit every `innerHTML` write site
- Replace `${name}` with `${escapeHtml(name)}` for any user-controlled string
- Add eslint rule blocking raw template interpolation in HTML context

### Phase 3J — Major version bump
- v4.0.0 in 3 places
- Service worker name bump
- BREAKING: agency-tagging migration; users may see warning at first load
