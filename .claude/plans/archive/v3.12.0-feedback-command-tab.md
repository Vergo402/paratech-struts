## Implementation

### Feature 1: Command tab separation

**Issue:** [#90](https://github.com/Vergo402/paratech-struts/issues/90)

**Symptom:** Operations tab currently hosts:
- Shore-point creation + workflow
- Apparatus assignment (`assignedApparatus` UI)
- External equipment management
- Individuals roster
- "My Role" picker
- ICS Organization (org chart)

This is too much for one tab. The IC needs a dedicated command surface; runners and cutting-table operators need a shore-point-focused surface.

**Investigate:**
- `index.html` — main tab nav (search for `#tab-operations`, the Operations tab content container, and nested sections for apparatus/individuals/org chart).
- `app.js` — `renderOperations()`, `renderOrgChart()`, `renderApparatusList()`, `renderIndividualsList()`, `renderExternalEquipment()`, `populateGroupDropdown()`, `sectionCollapsedState` keys for these sections.
- `style.css` — `.tab-content`, `.tab-nav`, tab icon assets.
- `manifest.json` — no change.

**Fix approach:**
1. **Add a new Command tab to the bottom nav.** Update tab order: Quick Find → Operations → **Command** → Inventory → Settings. Position it between Operations and Inventory so it's adjacent to where ops content lives today.
2. **Move these sections from Operations to Command:**
   - ICS Organization (`renderOrgChart()`)
   - Assigned Apparatus list + add-apparatus modal
   - External Equipment list + add-external modal
   - Individuals roster
   - My Role picker
3. **Operations tab retains:**
   - Active operation header / metadata
   - Shore point creation
   - Shore point cards with status workflow
   - Quick View FAB
4. **Cross-tab links:**
   - Group dropdown on shore-point creation still pulls from `assignedApparatus` — populates from same Firebase node, just rendered on a different tab.
   - Org-chart role assignments still reference apparatus and individuals — same source.
5. **Section-collapsed state:** keys `cmd-org`, `cmd-apparatus`, `cmd-external`, `cmd-individuals`, `cmd-myrole` (replace old `op-` prefixed keys for the moved sections). Migration: on load, copy old `op-*` keys to new `cmd-*` keys; clear old keys after one boot.
6. **NIMS doctrine alignment opportunity:** with apparatus moved off Operations, this is the natural moment to also implement the `group` → `assignedResource` dual-write (v3.12.0 was already the planned cutover window per CLAUDE.md). Roll this in if scope allows; otherwise tag for v3.12.1.
