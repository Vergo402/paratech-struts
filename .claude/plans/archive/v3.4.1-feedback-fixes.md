## Implementation

### Bug 1: Shore point "Assigned to" label (#55)

**Issue:** #55
**Symptom:** Active shore point cards show "Assigned to: {apparatus}" for the source apparatus. User says this is wrong — it should indicate where the equipment came from, not who's assigned to work the shore point.
**Context:** Feedback filed at v3.1.1 (2026-05-11), before #47 was fixed (v3.3.2). The label cleanup in v3.3.2 fixed the archived detail view but the active card label may still be misleading.

**Investigate:** `app.js` lines ~2809 and ~2919 — two render locations for shore point cards. Both currently show:
- External equipment: `"External equipment from: {deptName}"` ✅
- Normal equipment: `"Assigned to: {apparatusName}"` ← this is the source apparatus, not the assignment

The `sp.deployedStrut.apparatus` field stores which apparatus the equipment was deployed FROM (inventory source). Labeling it "Assigned to" is confusing because "assigned to" implies who's working the shore point.

**Fix:** Change label from "Assigned to:" to "Equipment from:" for non-external equipment in both render locations. This matches the external equipment pattern and is consistent with the v3.3.2 archived detail view fix.

```
Before: Assigned to: Rescue 56
After:  Equipment from: Rescue 56
```

Also check line ~375 in `renderResults()` which already correctly says "Equipment from:" — no change needed there.

### Bug 2: Result card shows wrong plate name (#56) — FIXED

**Issue:** #56
**Symptom:** Selecting Channel Base 4"x4" + Channel Base 6"x6" in the plate picker produces a result card that displays "Top: Hinged Base 12" · Sole Plate: Hinged Base 12"".
**Root cause:** `app.js` lines 347-348 in `renderResults()` look up plates by `height`, not `id`. Channel Base 4x4, Channel Base 6x6, and Hinged Base 12" all share `height: 3.4`, so `Array.find()` returns the first match — `hinged12` (which appears earlier in the BASE_PLATES array).
**Note on safety:** The height-based deduction is still correct (6.8" total for two 3.4" plates), so strut recommendations are NOT affected. But the displayed plate name is misleading.

**Fix:** Use the plate ID stored as `deductions.topPlateName` / `deductions.bottomPlateName` for the lookup, falling back to the height-based lookup for legacy data without name fields:

```javascript
// Before:
const p = BASE_PLATES.find(b => b.height === d.topPlate && b.id !== 'none');

// After:
const p = BASE_PLATES.find(b => b.id === d.topPlateName)
       || BASE_PLATES.find(b => b.height === d.topPlate && b.id !== 'none');
```

### Bug 3: Operations page sections start expanded (#57)

**Issue:** #57
**Symptom:** The "Assigned Apparatus", "External Equipment", "Individuals", and "My Role" collapsible sections at the top of the Operations page all start expanded. On mobile, this pushes the shore point cards (the actual operational content) far down the page.

**Investigate:**
- `index.html` lines 201-222 — Four `section-toggle` divs with `aria-expanded="true"` and arrows set to `▼`
- `app.js` line 3337 — `sectionCollapsedState` starts as `{}` (empty object = all expanded)

**Fix:** Initialize `sectionCollapsedState` with all four sections collapsed by default. Update the HTML to match (arrows = `▶`, `aria-expanded="false"`, content divs hidden).

In `app.js` line 3337:
```javascript
// Before:
let sectionCollapsedState = {};

// After:
let sectionCollapsedState = { apparatus: true, external: true, individuals: true, myrole: true };
```

In `index.html`, for each of the four sections:
- Change `aria-expanded="true"` → `aria-expanded="false"`
- Change arrow text `▼` → `▶`
- Add `style="display:none"` to content divs (`sectionApparatus`, `sectionExternal`, `sectionIndividuals`, `sectionMyrole`)

This way the sections are collapsed on page load but users can expand any section they need with one tap.
