# Plan: v3.16.0 — SmartArt ICS Org Chart

## Context

The existing ICS org chart (flat card grid with drag-and-drop reparenting) doesn't show hierarchy visually. Users couldn't tell at a glance who reports to whom or where span-of-control problems existed. v3.16.0 rebuilds it as a SmartArt-style interactive tree with L-shaped CSS connectors, per-node toolbar controls, and auto-centering scroll. The headline feature is already implemented on `feature/smartart-org-chart` (commit `f0314c9`); this plan covers the must-fix items from agent review, should-fix polish items, and user manual update.

The original v3.16.0 scope (scenario presets, solo-IC mode, Quick-start FAB) is deferred to v3.17.0 to keep this release focused on a single coherent feature.

## Implementation breakdown

### Item 1: Gate Add sub-role behind canReparent() — ALL sites + runtime guard
**Issue:** #96 item 1
**Files:** `app.js:6133-6134, 6186, 3552, 2118, 1942`
**Problem:** The `+` Add sub-role button is unconditionally rendered for all users at 4 separate sites. More critically, `addCustomRole()` at line 1942 has NO runtime `canReparent()` check — the CLAUDE.md claim that it does (at "app.js:1848") is stale/wrong. Any user can add org chart nodes via console even if UI buttons are hidden.
**Fix:**
- (a) Add `if (!canReparent()) { showToast('Only the IC can modify the chart', 'warning'); return; }` as the first line of `addCustomRole()` (defense-in-depth runtime guard).
- (b) Gate the `+` button render in `renderNode` (line 6134) behind `if (reparentOK)`.
- (c) Gate the `+ Role` header button at line 6186 behind `reparentOK`.
- (d) Gate the `+ Sub-Role` button in `openOrgChartNode` modal at line 3552 behind `canReparent()`.
- (e) Gate the `showAddRoleMenu` list items at line 2118 behind `canReparent()`.
**Ripple effects:** None — adds guards where none existed.

### Item 2: Remove Safety from canReparent() + update toasts
**Issue:** #96 item 2
**File:** `app.js:1812-1815, 2030, 2048, 2066, 2087`
**Problem:** `canReparent()` returns `true` for `myRole === 'safety'`. Per NIMS SM-0322, the Safety Officer reports directly to IC and has no supervisory authority over the organizational structure.
**Fix:**
- Change line 1814 from `return myRole === 'ic' || myRole === 'safety';` to `return myRole === 'ic';`
- Update 4 toast messages at lines 2030, 2048, 2066, 2087 from `'Only IC or Safety can reorder the chart'` to `'Only the IC can reorder the chart'`.
**Ripple effects:** The status-key hint at line 6192 says "rearrange" when `reparentOK` is true — still correct (just IC sees it now).
**NIMS note:** Safety's stop-work authority over life-safety operations (`SHORE_ACTION_ALLOWED_ROLES` at line 1826) is separate from org-chart restructuring authority and is NOT affected by this change.

### Item 3: Touch targets — mobile toolbar rework + 44px hit areas
**Issue:** #96 item 3
**File:** `style.css:1438, 1445, 1448, 1479-1488` and `app.js:6131-6145, 3550-3555`
**Problem:** `.org-tool` is 26×26px, `.org-card-btn` is 22×22px — both below WCAG SC 2.5.5 AA 44px minimum. On mobile ≤480px, cards are 110px wide and toolbar can have 5-7 buttons (5×44=220px — geometrically impossible).
**Fix — two-part:**
- **(a) Mobile ≤480px:** Hide reorder toolbar buttons (↑↓↰↳ + ＋) inline. Move them into the existing `openOrgChartNode()` modal that fires on card tap. Keep only collapse (▾) and delete (×) as inline `.org-card-btn` buttons in `.org-card-corner`. Drop the 110px mobile card width override — 132px minimum at all breakpoints.
- **(b) All viewports:** Increase `.org-card-btn` hit area to 44×44px via padding. On desktop (>480px), keep inline toolbar with `.org-tool` at 44×44px hit area:
```css
.org-tool {
  width: 44px; height: 44px;
  padding: 10px;
}
.org-card-btn {
  min-width: 44px; min-height: 44px;
  padding: 11px;
}
```
- **(c)** Widen `.org-node` from 132px to ~160px on desktop to accommodate the wider toolbar (5 buttons × 44px with overlap from padding = ~180px in toolbar, but `flex-wrap: wrap` can handle two rows if needed).
**Ripple effects:** Tree grows wider — verify auto-center scroll still works. Mobile modal approach needs the reorder controls added to `openOrgChartNode()`.

### Item 4: Granular sibling-pair update in moveRoleUp/Down
**Issue:** #96 item 4
**File:** `app.js:2029-2063`
**Problem:** Both `moveRoleUp()` and `moveRoleDown()` call `saveCustomRoles({ deletion: true })` — full-array `set()`. Violates v3.6.0 R3 concurrent-write doctrine.
**Fix:** Replace `saveCustomRoles({ deletion: true })` in both functions with:
```js
persistOperation();
if (db && deptId && activeOperation.id) {
  const ref = firebase.database().ref(`departments/${deptId}/operations/${activeOperation.id}`);
  const updates = {};
  updates[`customRoles/${idx}`] = roles[idx];
  updates[`customRoles/${prevIdx}`] = roles[prevIdx];
  firebaseSave(ref, 'update', updates);
}
```
Local-first `persistOperation()` writes full array to localStorage (correct). Only Firebase path changes to granular.
**Ripple effects:** None. `promote/demote` already use the granular `saveCustomRoles()` path (no `{deletion: true}`) which is acceptable since they modify a single role's `parentId`.

### Item 5: aria-labels on glyph toolbar buttons
**Issue:** #96 item 5
**File:** `app.js:6123, 6128, 6134-6144`
**Fix:** Add `aria-label` to each button:
- `＋` → `aria-label="Add sub-role"`
- `↑` → `aria-label="Move up"`, `↓` → `aria-label="Move down"`
- `↰` → `aria-label="Promote"`, `↳` → `aria-label="Demote"`
- `▾`/`▸` → `aria-label="Collapse branch"` / `aria-label="Expand branch"`
- `×` → `aria-label="Remove role"`

### Item 6: escapeAttr() on roleId — ALL 19 sites
**File:** `app.js:6123, 6128, 6134, 6136, 6137, 6141, 6144, 6154, 6157, 6158, 6161, 6162, 6164` (14 in renderNode) + `app.js:2118` (showAddRoleMenu) + `app.js:3552-3555` (openOrgChartNode modal, 4 sites)
**Problem:** `roleId` interpolated raw into onclick/ontouchstart/ondragstart/data-role attribute contexts at 19 sites total. Same class as X3 (fixed in v3.5.2 via data-attribute delegation).
**Fix:** `escapeAttr(roleId)` at all 19 sites. `escapeAttr()` is a no-op on safe strings — zero runtime cost.

### Item 7: Orphan parentId crash fix in renderSubtree — CRITICAL
**File:** `app.js:6196-6197`
**Problem:** Line 6197 accesses `.parentId` on the result of `.find()` INSIDE a template literal — the null guard cannot fire before the dereference. If a role's `parentId` references a deleted role, this throws `TypeError` and crashes the entire Command tab. Additionally, circular `parentId` references cause infinite recursion → stack overflow.
**Fix:** Restructure to guard before the template literal, and add a visited set with depth cap:
```js
const visited = new Set();
const renderSubtree = (roleId) => {
  if (visited.has(roleId)) return '';
  visited.add(roleId);
  const self = opRoles.find(r => r.id === roleId);
  if (!self) return '';
  let h = `<div class="org-node-wrap${!self.parentId ? ' is-root' : ''}">`;
  h += renderNode(roleId);
  // ... rest unchanged
};
```
**Ripple effects:** None — defensive guard only. Follows the same pattern as `isDescendantOf()` at line 1784.

### Item 8: clearTimeout on repeated renderCommand
**File:** `app.js:4409`
**Fix:** Module-scoped `let renderCommandScrollTimer = null;` — clear on entry, set on scroll:
```js
let renderCommandScrollTimer = null;
function renderCommand() {
  if (renderCommandScrollTimer) clearTimeout(renderCommandScrollTimer);
  // ... existing render logic ...
  renderCommandScrollTimer = setTimeout(() => { /* auto-center */ }, 0);
}
```

### Item 9: "You are now IC" toast on role assignment
**File:** `app.js` — inside `assignOrgChartRole()` or the handler that sets `myRole`
**Fix:** After `myRole` is set, show `showToast('You are now ${escapeHtml(roleName)}', 'success')`. Guard: only fire on explicit user action (check for a flag like `isUserAction` parameter), not on listener re-hydration from Firebase.

### Item 10: touch-action for iOS drag compatibility
**File:** `style.css`
**Fix:** Add to org chart CSS block:
```css
.org-tree-canvas { touch-action: pan-x; }
```
During drag operations, the drag-start handler should set `touch-action: none` on the dragged `.org-node` element and restore it on drag-end.

### Item 11: Disabled button outdoor readability
**File:** `style.css:1448`
**Problem:** `opacity: 0.28` on `--text-secondary` collapses to below 2:1 contrast in direct sunlight — invisible.
**Fix:** Replace:
```css
.org-tool.is-disabled, .org-tool[disabled] {
  color: var(--text-disabled);
  opacity: 1;
  cursor: not-allowed;
}
```
Uses the established `--text-disabled` token which passes 3:1 for UI components in both light and dark mode.

### Item 12: Cycle guard in getSubtreeIds
**File:** `app.js:2800-2810`
**Problem:** BFS queue has no visited-set guard — circular `parentId` causes infinite loop.
**Fix:** Add `if (ids.has(id)) continue;` before `queue.push` in the while loop. (`ids.add(id)` already exists — just add the guard check before the push.)
