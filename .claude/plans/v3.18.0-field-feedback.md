**Battalion-chief narrowing (mandatory):** Ops gains `mark-cut-done` and `send-to-runner` only. Ops does NOT gain `mark-secured` (v3.17.0 #104 doctrine — FEMA ICSSCI SM-0322) and does NOT gain `return-equipment` (physical custody — must stay with the resource holding the equipment, else phantom inventory misleads incoming IC at command transfer).

**Fix scope (final):**
- `mark-cut-done`: add `operations` → `['cutting', 'wood', 'ic', 'safety', 'operations']`
- `send-to-runner`: add `operations` → `['cutting', 'runner', 'ic', 'safety', 'operations']`
- `mark-secured`: **unchanged** (`['ic', 'safety', 'shoring', 'wood']`)
- `return-equipment`: **unchanged** (`['return-equipment', 'ic', 'safety']`)

**Code comment requirement (per code-auditor + battalion-chief):** Add a comment block at `SHORE_ACTION_ALLOWED_ROLES` explaining: Ops is command authority through `secured`; physical-custody actions (`mark-secured` and `return-equipment`) stay with hands-on-the-equipment roles to preserve accountability at command transfer. Reference v3.17.0 #104 + battalion-chief 2026-05-20 review.

**Verification (per qa-driver):** Full permission matrix — 6 transitions × {Ops, IC, Safety, Shoring, Cutting, no-role} = drive every cell. ### #116 — External equipment doesn't update available inventory (Critical, fullstack-engineer · Sonnet 4.6 · Medium)
**Symptom:** Adding external equipment to an operation does not decrement available inventory; the inventory column doesn't refresh.
**Investigate:** `addExternalEquipment()` or `confirmAddExternal()` in app.js, plus the renderInventory() call sites added in v3.8.0 (#64 fix). The v3.17.0 #102 form rebuild may have lost the post-add render call.
**Fix approach:** Trace add-external flow end-to-end: ensure `persistInventory()` runs after add, ensure `renderInventory()` follows it, ensure the available-count math accounts for `type: 'external'` items.
**Verification:** Preview UI driver — start op with apparatus, add 2 external struts, confirm available count drops by 2 and Quick View shows correct remaining.

### #117 — Header pushed left when switching to Operations (High, mobile-ux · Sonnet 4.6 · Low)
**Symptom:** When the inventory right rail (v3.16.1) is shown on the Operations tab on desktop, the header is pushed out of center.
**Investigate:** style.css for the desktop Operations layout — the inventory column likely consumes flexbox space that the header was relying on for centering.
**Fix approach:** Pin header to viewport width or wrap header in a sibling-to-content container that doesn't share width with the inventory column.
**Verification:** Preview UI driver at 1280px width — switch between Quick Find / Operations / Command tabs and confirm header logo/title stays centered, no left-shift on Operations.

### #115 — Apparatus column layout (High, mobile-ux · Sonnet 4.6 · Medium)
**Symptom:** From the screenshot — DEPUTY CHIEF / SQUAD / RESCUE / ENGINE / LADDER labels float mid-row between chips, not above/grouped with their apparatus. Single-file line, unjustified.
**Investigate:** The renderer for Command-tab "Assigned Apparatus" section. Currently appears to inline-wrap chips with category labels as siblings; needs to group chips under their category label.
**Fix approach:** Restructure markup as `<section><h4>Category</h4><div class="chips">...</div></section>` per category. Empty categories hidden. CSS: chips wrap as a grid within each category section.
**Verification:** Preview UI driver — assign 8 apparatus across 5 categories (the screenshot scenario), confirm each category renders as a labeled block with its chips grouped beneath, properly wrapped on phone and desktop widths.

### #122 — Remove Quick Select scenario presets (Medium, fullstack-engineer · Sonnet 4.6 · Low)
**Symptom:** Scenario preset buttons ("Car into building" / "Residential" / "Light commercial") in the Start-Op modal add cognitive load at incident-start.
**Investigate:** The Start-Op modal markup in index.html + `scenarioPresets` config in app.js (v3.17.0 #108).
**Fix approach:** Remove the preset row from the modal. Delete the preset config + handler code. Keep org chart preset (Type IV/V default) — that's separate and survives. Document the removal in commit message with v3.17.0 #108 reference.
**Verification:** Preview UI driver — open Start-Op modal, confirm no preset row, confirm modal still functions (name + apparatus + start).

### #124 — Remove auto/solo/promote (Medium, fullstack-engineer · Sonnet 4.6 · Medium)
**Symptom:** "Auto — Standard mode (8 apparatus) / Stay in solo mode" radio block (visible in screenshot) confuses users by exposing internal mode logic.
**Investigate:** The solo-IC progressive disclosure code from v3.17.0 #109. Look for `soloMode`, `autoPromote`, `apparatusCount > 1 → promote` logic.
**Fix approach:** Remove the entire progressive-disclosure mechanic. The Command-tab UI always renders in "Standard mode" regardless of apparatus count. Solo IC sees the same full Command view. Delete the mode-radio markup. Delete the auto-promote handler. Delete the solo-mode CSS class branches.
**Constraint:** Don't break the apparatus-selection ergonomics — if only one apparatus exists at op-start, it should still auto-select in the Start-Op modal (that's a different convenience, not solo mode).
**Verification:** Preview UI driver — start a 1-apparatus op, confirm Command view shows full layout (no "solo mode" branding, no auto-promote radio). Add 2nd apparatus, confirm no mode-transition animation/state change.

### #125 — Bigger Command dashboard tiles (Medium, mobile-ux · Sonnet 4.6 · Medium)
**Symptom:** Timer, apparatus count, SP count too small on Command page; not integrated as dashboard tiles.
**Investigate:** Command-tab header markup in index.html, currently inline metadata. Field user (Alex) explicitly says "The shore point workflow is great for right now, don't alter that" — touch only the dashboard, not the SP cards.
**Fix approach:** Restructure Command top section as three dashboard tiles in a row:
  - **Timer tile** — HH:MM:SS in monospace large type, label "ELAPSED" (32px+ font-weight 800; field-conditions legibility)
  - **Apparatus tile** — count + chip list summary (28px+ font-weight 800)
  - **Shore Points tile** — count + per-status breakdown (pending/cutting/secured/etc.)

On phone, tiles stack vertically. On desktop, three-column grid. Timer tile gets vertical padding `20px 16px` vs. `14px 12px` on count tiles — establishes hierarchy without custom height.

**Implementation constraint (mandatory per mobile-ux):** Timer MUST be driven by a dedicated `setInterval` writing directly to the timer element's `textContent`, NOT by re-rendering the full Command tab every second. Pattern: `opTimerInterval` module-level ref, started on op-load/tab-switch-into-Command, stopped on op-end or tab-leave. Re-rendering `renderCommand()` every second causes visible flicker and wastes layout cycles on gloved-screen swipes.

**Battalion-chief addition (recommended):** Consider a 4th tile or a red-dot badge for unfilled command positions, especially **Safety Officer unassigned**. At command transfer, an incoming IC needs that signal in the first 2 seconds without scrolling the org chart. v3.18.0 minimum: add a red dot badge to the org-chart section header when Safety is unassigned. 4th tile deferred to v4.0.0 unless layout absorbs it cleanly.

**Verification:** Preview UI driver at six widths (375 / 414 / 768 / 1024 / 1280 / 1920px). Timer ticks HH:MM:SS every second (confirmed via DOM observation, no full re-render). Apparatus/SP counts update when items added/removed. Test iOS PWA add-to-home-screen mode — `setInterval` survives background/foreground cycle.

### #121 — Sort available plates to top of dropdown (Low, mobile-ux · Haiku 4.5 · Low)
**Symptom:** Plate dropdown shows all plates in alpha/numeric order; available (in-inventory) plates intermixed with unavailable.
**Investigate:** `openPlatePicker()` or the plate dropdown render in app.js.
**Fix approach:** Sort: available plates first (preserving alpha/numeric within), then unavailable plates (preserving alpha/numeric within).

**Mobile-ux requirement (mandatory):** Add a visual section-label divider between the two groups — `"Available"` and `"Not in inventory"` rows. Silent sort alone fails under gloves (user mental model: "if I scrolled to the bottom, I'm in unavailable plates" — without a label that breaks). Divider: `<div class="picker-section-label">` with `grid-column: 1 / -1` to span full bottom-sheet grid width. Style: `font-size: 11px`, `text-transform: uppercase`, `color: var(--text-hint)`, `padding: 4px 8px`. Subordinate to plate buttons.

**Constraint:** The plate picker uses `visibility` toggle (not `display`) per the v3.5.1 iOS scroll fix in CLAUDE.md. Section-label divider must not break that — verify bottom-sheet scroll still works after the grid gains a spanning child on iOS preview.

**Verification:** Preview UI driver — open plate picker on an SP with partial inventory; confirm "Available" label, then in-stock plates in original order; then "Not in inventory" label, then out-of-stock plates in original order. Confirm on iOS preview that bottom-sheet swipe-scroll still works.
