## Scope (execution order: #80 → #284 → #300 → #103; #123 independent)

### 1. #80 — Concurrent deploy phantom-double allocation (Critical) — **DESCOPED**
**devops-resilience · Opus 4.7 · High.** The v3.15.0 `makeAllocateDecrementer` fix closed the narrow online last-strut case; three residual races remain. Ship the cheap fixes; defer the ledger.

**Fix A — clamp the unclamped compensation (Race A).** `runDeployTransactions` compensation at **app.js:7912** is `(v)=>v+1` with no ceiling → can inflate `available` past `quantity` (phantom inventory). Clamp to `quantity`. **The closure doesn't currently have `quantity` in scope** — thread it into the guard objects pushed at **app.js:7858/7873/7897** (strut: `strutInvItem.quantity`; ext: `activeOperation.externalEquipment[id].quantity`; plate: `plInv.quantity`).

**Fix B — numeric-validate external equipment (Race C).** `externalEquipment/$itemId/{available,quantity}` has **no `.validate`** today (only `_meta` is guarded; `.validate` on a sibling doesn't constrain others). Add at the exact path `departments/$deptId/operations/$opId/externalEquipment/$itemId/available` (and `/quantity`): `newData.isNumber() && newData.val() >= 0 && (!newData.parent().child('quantity').exists() || newData.val() <= newData.parent().child('quantity').val())`. Note "mirror the inventory rule" is **insufficient** — the inventory rule is `hasChildren`-only, not numeric-typed; this must be stronger. Optionally tighten `inventory` `available`/`quantity` to `isNumber()` too (defense-in-depth).

**Fix B′ — coerce the unescaped render (live stored-XSS).** **app.js:5122** interpolates `${ext.available}/${ext.quantity}` **raw**; with Race-C's unvalidated fields this is a stored-XSS vector that #123's drilldown multiplies. `Number(ext.available)||0` / `Number(ext.quantity)||0` at every interpolation (mirror the v3.9.0 `Number(ext.length)` pattern).

**Fix C — delta-aware offline reconciliation, BOTH pipes (Race B, the real phantom-double).** Offline deploy is unbounded; the touched-set flush writes the **absolute** `localAvail`, so two offline deploys of the last unit both converge `available→0`, *hiding* the double. Change the touched record `{localAvail}` → `{baselineAvail, delta}` and flush `transaction(v => v===null ? undefined : clamp(v+delta, 0, quantity))`. **CRITICAL — there are TWO touched-pipes and FOUR readers, not one:**
- internal: `markOfflineTouched` (app.js:1055), `flushOfflineTouchedInventory` (1100), `applyOfflineTouchedFilter` (1079)
- external: `markOfflineTouchedExternal` (1032), `flushOfflineTouchedExternal` (1205), operations-listener shim (2934)

Migrate **all six**. Add a shared `readTouchedAvail(entry, currentVal)` accessor applied at every read site for in-flight old-`{localAvail}` entries (the touched-set is **not** version-gated, so the shim is load-bearing, not optional). When the clamp floors at 0 **with residual delta**, that's the detected over-allocation: emit `logSyncEvent('phantom_double_detected', …)` AND surface it (Fix D).

**Fix D — surface the conflict persistently (not a toast).** Per battalion-chief: a toast is lost at scale. On a detected over-allocation, flag the affected **shore-point card** with a persistent **"VERIFY PHYSICAL STRUT"** badge (amber) that does **not** auto-clear until IC/Safety acknowledges; the flagged SP must **not** count as secured/deployed in the Command dashboard pills.

**DEFER to v4:** L1 allocation-ledger (`operations/{opId}/allocations`) + L3 server-authoritative Cloud Function (no `functions/` dir exists). These need the multi-device model + `config/minAppVersion` enforcement (rules:124) that live in v4 — and L1's guarantee is void in a mixed-version fleet anyway.

**Verification:** two-client offline→reconnect for **both an internal strut AND an external strut** (assert the double is surfaced, not silently 0); partial-abort compensation never exceeds `quantity`; out-of-bounds external decrement rejected by the rule; the persistent flag appears and survives re-render.
