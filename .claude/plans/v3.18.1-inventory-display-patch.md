## Investigation findings

### Bug #126 — Ghost inventory (`renderQuickViewInventory`)
**Issue:** #126
**Symptom:** User has no apparatus assigned to the operation, but the Quick View panel shows Eng 168, E170, R56 as "available" inventory — apparatus that belong to the department but are not part of this incident.
**Root cause:** `renderQuickViewInventory()` at `app.js:8356` reads `localInventory.filter(i => i.apparatus)` with no filtering by the operation's `assignedApparatus`. Every apparatus in the department's inventory passes the filter.
**Fix:** When an active operation exists, filter `localInventory` to items whose `apparatus` is in `activeOperation.assignedApparatus`. The fix MUST distinguish three states (per GATE 2 review):
1. No active operation → show all (Inventory tab fallback)
2. Active operation + apparatus assigned → filter by assignment
3. Active operation + zero apparatus assigned → show empty state with prompt

State 3 is the actual hfd217 case. Earlier draft collapsed states 1 and 3 into "show all"; corrected below.

**Verification:** Start an op with Eng 168 assigned. Add E170 to dept inventory but do NOT assign it to the op. Open Quick View — should show only Eng 168 items. Then: start an op with no apparatus assigned. Open Quick View — should show "Assign apparatus to this operation" prompt, NOT all dept inventory.

## Implementation

### Fix — `renderQuickViewInventory()` filter by assigned apparatus (corrected per GATE 2)

**File:** `app.js:8354`
**Function:** `renderQuickViewInventory()`

Current line 8356:
```javascript
const items = localInventory.filter(i => i.apparatus);
```

Change to:
```javascript
// v3.18.1 #126: gate filter on activeOperation existence, NOT on
// assignedApparatus.length. An active op with zero assigned apparatus is a
// deliberate empty state — "you have not assigned apparatus yet" — not the
// pre-op fall-back state. Collapsing the two showed all dept inventory in
// hfd217's case where the op was started without assignment.
const assignedSet = activeOperation
  ? new Set(activeOperation.assignedApparatus || [])
  : null;
const items = localInventory.filter(i => i.apparatus && (!assignedSet || assignedSet.has(i.apparatus)));
```

Behavior matrix:
| State | `activeOperation` | `assignedApparatus.length` | `assignedSet` | Filter result |
|---|---|---|---|---|
| Pre-op (Inventory tab) | null | n/a | null | shows all `i.apparatus` items |
| Op + apparatus assigned | obj | > 0 | Set with IDs | shows only matching apparatus |
| Op + zero assigned | obj | 0 | Set with 0 items | shows nothing → empty state |

Also update the empty-state branch at line 8358–8360 to distinguish "no apparatus assigned to operation" from "no equipment on assigned apparatus":

```javascript
if (items.length === 0) {
  const msg = (assignedSet && assignedSet.size === 0)
    ? 'No apparatus assigned to this operation. Assign apparatus from the Operations tab to see available inventory.'
    : 'No equipment assigned to apparatus';
  body.innerHTML = `<div style="padding:24px;text-align:center;color:var(--text-secondary)">${msg}</div>`;
  return;
}
```
